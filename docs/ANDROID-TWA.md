# פרסום ל-Google Play כ-TWA

עטיפת ה-PWA הקיים באפליקציית אנדרואיד, **בלי לשנות שורת קוד באפליקציה עצמה**.
האפליקציה טוענת את אותו אתר שכבר פרוס; מה שמשתנה הוא רק האריזה.

---

## מה כבר מוכן בריפו

| | |
|---|---|
| `manifest.json` | תקין, `standalone`, אייקונים 192/512 כולל `maskable` |
| `sw.js` | Service Worker, עבודה אופליין |
| `#/terms`, `#/privacy-policy` | דרישת סף של Play — קיימות |
| מחיקת חשבון מתוך האפליקציה | דרישת Play מאז 2023 — קיימת (`deleteAccountBtn`) |
| `.well-known/assetlinks.json` | קיים, עם מציין-מקום אחד לטביעת האצבע |
| `twa/twa-manifest.json` | קונפיגורציית Bubblewrap מוכנה |
| `scripts/check_twa.js` | בודק שהשלושה לא יצאו מסנכרון |

**מה שחסר תלוי בחשבון Play Console בלבד** (25$ חד-פעמי).

---

## למה טביעת האצבע הכרחית

`assetlinks.json` הוא כל מה שמפריד בין "אפליקציה שמציגה את האתר שלך במסך מלא" לבין
"כל אחד יכול לעטוף את האתר שלך ולפרסם בשמו". טביעת האצבע היא ההוכחה ששני הצדדים
שייכים לאותו בעלים.

בלעדיה שום דבר לא נשבר בקול — Chrome פשוט לא מאמת, והאפליקציה נפתחת עם **שורת כתובת
גלויה**. זה הכישלון היחיד שצריך לשים לב אליו, כי הוא שקט.

**אתה לא מייצר אותה.** Play App Signing מחזיקה את המפתח; אתה מעתיק מחרוזת מוכנה.

## הצעדים, לפי הסדר

### 1. להחליט על שם החבילה — **החלטה בלתי הפיכה**

`il.co.megalimisrael.app`, כרגע ב-`twa/twa-manifest.json` וב-`.well-known/assetlinks.json`.

אחרי הפרסום הראשון **אי אפשר לשנות אותו לעולם**. שינוי מחייב אפליקציה חדשה, עם
דירוגים והתקנות מאפס. זה לא חייב להתאים לדומיין (בניגוד ל-`host`, שכן חייב).
אם רוצים משהו אחר — לשנות **עכשיו**, בשני הקבצים, ולהריץ `node scripts/check_twa.js`.

### 2. להתקין ולבנות

```bash
npm i -g @bubblewrap/cli
cd twa
bubblewrap init --manifest=https://megalim-israel.co.il/manifest.json
bubblewrap build
```

`bubblewrap init` מייצר `twa-manifest.json` משלו ועובר על השדות באופן אינטראקטיבי.
הקובץ שכאן הוא **התשובות שצריך לתת** — ערכי הצבעים, האייקונים, שם המשגר וההעדפות
כבר גזורים מ-`manifest.json` האמיתי. אם גרסת Bubblewrap שלך דוחה שדה כלשהו, היא
מקור-האמת; עדכן את הקובץ כאן כדי שהבדיקה תישאר רלוונטית.

> **שווה לבדוק:** ל-Bubblewrap יש תמיכה ב-*location delegation* — העברת הרשאת
> המיקום דרך הרשאת האנדרואיד של האפליקציה עצמה. זה בדיוק מה שהיה מבלבל ב-WebAPK.
> לא אימתתי את שם הדגל המדויק בגרסה הנוכחית; חפש אותו ב-`bubblewrap init` ובתיעוד.

הפלט הוא `app-release-bundle.aab`.

### 3. Play Console

1. חשבון מפתח, 25$ חד-פעמי
2. ליצור אפליקציה עם שם החבילה מצעד 1
3. להעלות את ה-AAB למסלול **Internal testing** — לא לייצור, לא עדיין

### 4. טביעת האצבע — חמש דקות

Play Console ← **Setup** ← **App integrity** ← *App signing key certificate* ←
להעתיק את **SHA-256**.

להדביק ב-`.well-known/assetlinks.json` במקום `REPLACE_WITH_SHA256_FROM_PLAY_CONSOLE`,
ואז:

```bash
node scripts/check_twa.js   # מאמת צורה, ושהחבילה זהה בשני הקבצים
git commit && git push      # Vercel פורס; הקובץ חייב להיות חי לפני הבדיקה הבאה
```

### 5. לאמת שהאימות עובד

להתקין את גרסת ה-Internal testing ולפתוח.

- **אין שורת כתובת** → האימות עבר. זהו.
- **יש שורת כתובת** → assetlinks לא אומת. לבדוק לפי הסדר:
  `https://megalim-israel.co.il/.well-known/assetlinks.json` מחזיר 200 עם
  `application/json`; טביעת האצבע היא של **מפתח החתימה של Play** ולא של מפתח
  ההעלאה (שתי מחרוזות שונות באותו מסך — זו הטעות הנפוצה); שם החבילה זהה בשני הצדדים.

> אם הכתובת מחזירה 404: תיקיות שמתחילות בנקודה לא תמיד נכללות בפריסה סטטית.
> הפתרון הוא `vercel.json` עם rewrite מ-`/.well-known/assetlinks.json` לקובץ.
> שווה לבדוק את הכתובת בדפדפן לפני שמאשימים את טביעת האצבע — זה נראה בדיוק אותו דבר
> מצד האפליקציה.

### 6. חומרי החנות

- צילומי מסך טלפון: לפחות 2, מינימום 320px בצלע הקצרה
- Feature graphic: 1024×500
- אייקון חנות: 512×512 (`icon-512.png` מתאים)
- תיאור קצר וארוך, בעברית
- **Data safety**: מיקום, אימייל, תמונות, תוכן משתמש — להצהיר על כולם
- קישורי מדיניות פרטיות ותנאי שימוש → `#/privacy-policy` ו-`#/terms`
- שאלון דירוג תוכן

### 7. לייצור

מ-Internal testing ל-Production. הביקורת הראשונה של חשבון חדש עשויה לקחת מספר ימים.

## תחזוקה שוטפת

עדכון תוכן באפליקציה **לא מצריך שום דבר** — היא טוענת את האתר החי, והפריסה ל-Vercel
מגיעה למשתמשים מיד. בנייה והעלאה מחדש נדרשות רק לשינוי אייקון, שם, צבעי מערכת, או
שדרוג Bubblewrap. אז גם צריך להעלות את `appVersionCode` ו-`appVersionName`.

`node scripts/check_twa.js` לפני כל בנייה.

## מה שה-TWA לא פותר

- **iOS** — אפל לא מקבלת PWA לחנות. חייב Capacitor.
- **Push notifications** — אפשרי דרך TWA, אבל דורש backend שליחה שלא קיים היום.
